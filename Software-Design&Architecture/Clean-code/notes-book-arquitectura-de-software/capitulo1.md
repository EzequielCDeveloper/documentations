# Capitulo 1: La arquitectura y el desarrollo de software

## Vision general del desarrollo de sistemas de software

**_software:_** Es la solucion tecnica de un problema.
**_Requerimientos:_** Se refiere a la problematica a resolver o las funciones por las que alguien estaria interesado en nuestro sistema.
**_Diseno:_** Es la propuesta a hacer de como sera nuestro sistema de software que resolvera dicha problematica.
**_Construccion:_** Se esta refieriendo a la Construccion/programacion del sistema a resolver.
**_Pruebas:_** Es la parte en la que corroboramos que lo construido cumple con los Requerimientos establecidos.
**_Implantacion:_** Cuando se coloca el sistema para su pleno uso para el que fue desarrollado.

_La arquitectura de un sistema es el conjunto de estructuras necesarias para razonar sobre el sistema. Comprende elementos de software, relaciones entre ellos y propiedades de ambos._ (**Bass, Clements y Kazman, 2012**)

## Definicion de arquitectura de software

Es un termino que no necesariamente tiene una Definicion estricta.

> _La arquitectura de un sistema es el conjunto de estructuras necesarias para razonar sobre el sistema._  
> _Comprende elementos de software, relacionados entre ellos y propiedades de ambos_ (**Bass, Clements y Kazman, 2012**)

### Que es un elemento de software?

Los elementos se les debe considerar como partes del sistema, podriamos dividir el sistema en modulos que representan funciones, logica etc. fragmentos que componen al sistema de software.
Ademas de como modulos, tambien podemos considerar a los elementos de software como:

- Entidades dadas en el tiempo de ejecucion, es decir, dinamicas, como objetos e hilos.
- Entidades que se presentan en el tiempo de desarrollo, es decir logicas, como clases y modulos.
- Entidades del mundo real, es decir fisicas, como nodos o carpetas.
